## Genuinely missing, ranked by what actually loses a deal against OpenBOM

1. **Webhooks that never fire (+ no event catalogue).** `webhook_service.py:195` is only reachable from `test_webhook` and `retry_delivery`. This is the worst finding in the audit because the doc marks it ✅ and the UI presents a working subscription manager, so a buyer discovers it only after integrating. OpenBOM ships a rich event set. Fixing it is small — one `emit()` helper called from the existing service layer, matched against `webhook_subscriptions.events`.
2. **CSV/XLSX import that does not create anything.** OpenBOM's entire onboarding motion is "drag your spreadsheet in". Here, the server-side pipeline (`bulk_import.py:71-98`) stages rows and stops, and the client-side modal only fills an unsaved grid. XLSX is not readable at all. This blocks day-one evaluation, which is exactly when a buyer compares the two.
3. **No non-SolidWorks CAD connector.** Fusion 360, Onshape and Altium are each literally zero lines. OpenBOM leads with exactly this breadth, and an ECAD/Altium gap eliminates every electronics customer regardless of how good the RoHS/REACH engine is. The SolidWorks add-in proves the team can build one properly, which makes the absence of the others the clearest competitive line.

Honourable mentions that matter to a buyer but rank below the three above: **API-key scopes displayed but not enforced** (`deps.py:80` — a security misrepresentation, not just a gap); **hardcoded vendor quality metrics** rendered as real data (`analytics.py:272-274`); and **contracts + lot/serial traceability**, both of which are fully built backends that need only a screen each — the cheapest wins on this list.
