## Genuinely missing, ranked by weight to a BOM/PLM buyer comparing against OpenBOM

1. **Real-time simultaneous editing is one wiring change from working, and today is broken.** This is OpenBOM's patented headline feature and the doc's own #1 CRITICAL. The entire server side is built (`main.py:368-591`) and the client provider is written (`collaboration.jsx:7`) — but `CollabProvider` is never mounted, so `bom-editor.jsx:811` renders a presence bar permanently wired to a no-op stub that shows "offline". A demo today would show a dead collaboration bar. Highest value-per-line-of-code item in all three domains.
2. **Serial/lot traceability has no screen.** Three tables, ten routes, a finished API client and a data-bridge entry — and not one component reads them. Any regulated-industry buyer (aero, med device, auto) asks for as-built serial genealogy in the first demo; right now the answer is "the data model supports it", which loses to Arena on the spot. Same shape, smaller stakes, applies to **inspection plans** (test requirements per part) and the **calendar_events** table.
3. **Requirements management does not exist at all** — no table, no route, no UI. This is the one item in domain 9 with nothing behind it, and it is the standard Arena/Teamcenter/Windchill differentiator versus OpenBOM. It is also the largest genuine build of anything listed here.

Runners-up, in order: **SSO frontend is a `setTimeout` stub that logs in as a hardcoded admin** (`auth-onboarding.jsx:87-98`) while a real OAuth2 backend sits unused — an enterprise-blocking defect that reads worse than "not built"; **SAML has zero live endpoints** despite the router being registered; **GDPR has literally no code** (portability only, no erasure); **horizontal scaling is blocked by in-process WebSocket state** with no Redis fan-out; **tooling** remains free-text.
